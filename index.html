File chỉ được xử lý trên thiết bị của bạn.

Chọn trực tiếp file .ipa, không cần đổi tên thành .zip. Tab Batch cũng nhận nhiều file .ipa cùng lúc (khung chọn không giới hạn đuôi file).

Nếu iPhone không cho chọn file .ipa, hãy đổi tên một bản sao thành .zip rồi chọn file .zip đó.

File chỉ được đọc và xử lý trong trình duyệt của bạn. Bản web giới hạn file ≤2GB; file lớn hơn hãy dùng bản iSH. Lưu ý: file gần 2GB vẫn có thể làm Safari trên iPhone văng tab vì RAM (tab Safari chỉ dùng được khoảng 1–1,5GB) — với file lớn nên dùng bản iSH cho chắc. Lần mở trang đầu cần mạng để tải Pyodide; sau đó xử lý hoàn toàn trên máy bạn, trừ khi bạn bật dịch Google ở tab Dịch (cần mạng).

Chức năng

File gần đây

Chỉ liệt kê file bạn đã chọn trong phiên này (tên, dung lượng, loại, thời gian). Metadata được lưu vào bộ nhớ trình duyệt để hiện lại sau khi tải lại trang — không lưu nội dung file. Nút “Chọn lại file” ở mỗi dòng: file còn trong phiên thì mở lại ngay đúng tab làm việc (file game → tab Danh sách, file .json → tab Mod); hết phiên thì mở hộp chọn file để bạn chọn lại file đó từ máy — nếu chọn nhầm file khác, trang báo rõ rồi vẫn mở file vừa chọn. Nút “Tải lại” chỉ hiện khi file còn trong phiên (tải 1 bản sao của file về máy). Tắt lưu lịch sử ở Cài đặt nếu không muốn lưu metadata.

Chưa có file nào trong phiên này — chọn 1 file game ở khung trên.

Thông tin Unity

Chưa có dữ liệu — chọn 1 file Unity rồi bấm Inspect ở Chức năng → Unity, phiên bản Unity sẽ hiện tại đây (chỉ hiện sau khi inspect thật, không bịa sẵn).

An toàn & Riêng tư

Giới hạn của bản web (đo thật, xem README)

  • Không dùng UnityPy (không cài được trên Pyodide — thiếu wheel etcpak). Inspect Unity dùng parser thuần của PB3.
  • Batch chạy song song thật trên pool worker (mặc định 2 worker — 2 thread hệ điều hành thật, mỗi worker chạy một game; chỉ bên trong một worker thì Python chạy tuần tự vì Pyodide không có pthreads). Trích xuất từng game vẫn chạy tuần tự trong worker của nó. Số worker chọn được 1–2 ở tab Batch (tự động 1 khi RAM thiết bị ≤ 4 GB).
  • KB tự lưu vào IndexedDB sau mỗi thay đổi và khôi phục khi mở lại trang; Safari vẫn có thể xóa dữ liệu web sau ~7 ngày không mở trang nếu chưa cài vào Màn hình chính — xuất file .sqlite sao lưu định kỳ (tab KB nhắc khi quá 7 ngày hoặc chưa từng xuất).
  • Mod chỉ xuất đơn vị nhỏ nhất đã patch (bundle/.assets), không đóng gói lại IPA; mặc định dry-run, chỉ ghi khi bạn bấm nút ghi rõ ràng.
  • Ma trận hỗ trợ: cột “ngày test” hiện “chưa có” vì bản web không kèm file bằng chứng tests/corpus/*.json.
  • Dịch Google cần mạng; Google có thể giới hạn tốc độ (HTTP 429) hoặc trình duyệt chặn CORS — khi đó tự động thử MyMemory rồi dùng từ điển offline và báo rõ lý do. Chưa thử dịch Google trên Safari thật. Có thể cấu hình proxy Cloudflare Worker (ô URL proxy ở tab Dịch, xem cloudflare/README.md) để tránh CORS/429 — proxy có hạn mức cứng 500.000 ký tự/tháng, hết hạn mức tự rơi về MyMemory + offline, không phát sinh phí.
  • Asset nhị phân (texture/âm thanh): chỉ đọc, dùng bản iSH. Bản web xem được tên, kích thước, hex, chuỗi text trong asset, nhưng không giải mã texture (DXT/ASTC/ETC2/PVRTC) hay âm thanh (Vorbis/MP3/AAC) để xem trước — xem texture/nghe âm thanh thì dùng bản iSH.
  • File đầu vào tối đa 2GB trên web (bằng bản iSH); file gần 2GB vẫn có thể làm Safari trên iPhone văng tab vì RAM.
  • Chưa thử trên iPhone thật — tốc độ và RAM trên Safari di động chưa đo.

Mã nguồn PB3 (BearTea) — xem README.md trong repo.

Danh sách entry trong file

Liệt kê các entry của ZIP/IPA (tên, loại, kích thước).

Inspect Unity

Đọc bundle .unity3d hoặc file .assets độc lập bằng parser thuần của PB3 (UnityFS v6–v9 — v9 chỉ đọc; block nén Zstd đọc được qua fzstd, SerializedFile v23). Không dùng UnityPy trên web. Nếu file đang chọn là ZIP/IPA thì trang liệt kê các bundle/.assets bên trong để bạn chọn 1 cái inspect trực tiếp. Asset nhị phân (texture/âm thanh): chỉ đọc, dùng bản iSH.

Chưa chọn file — chọn file ở Trang chủ (khung thả file) rồi quay lại đây.

“Xem sâu” liệt kê từng bundle/.assets trong file (tên, kích thước, version, nén, số object, nguồn ngôn ngữ, lý do pipeline bỏ qua). “Trích sâu” là chế độ last-resort, chỉ chạy khi bấm nút: kết quả ghi nhãn unverified (il2cpp-literals / unverified-raw-scan), tách riêng khỏi file locale chính — không trộn vào en.json/zh.json. Với IPA, nhập đường dẫn 1 entry: global-metadata.dat để đọc literal IL2CPP chính xác, hoặc data.unity3d để quét payload bundle đã giải nén.

Tùy chọn nâng cao

Inspect không có tùy chọn nào thêm — mọi bundle/.assets đều được đọc bằng cùng một parser thuần (UnityFS v6–v9, v9 chỉ đọc; block Zstd đọc qua fzstd; SerializedFile v23). Kết quả inspect (Unity Version, số object, TextAsset) hiện ở dưới và ở thẻ “Thông tin Unity” trên Trang chủ.

Trích xuất text

Chạy pipeline trích xuất đầy đủ của PB3, xuất các bảng key-value ra file JSON. Kết quả tải về dạng extract.zip.

AssetsResourcesTextAssetAudioTextureOthers

Trích xuất text từ mọi loại asset kể trên — bản web không lọc theo loại (muốn lọc thì dùng bản iSH). Asset nhị phân (texture/âm thanh): chỉ đọc tên và chuỗi text, không giải mã — dùng bản iSH. Tên file xuất: extract.zip — lưu bằng nút “Lưu / Chia sẻ” ở thanh Lưu file bên dưới.

Chọn file trong IPA/ZIP

Mặc định Tự động: tool tự tìm đúng file (tự mở bundle localization trong IPA, tự lấy en.json/zh.json ra) — không cần chọn tay. Chỉ dùng Chọn tay để thu hẹp khi bạn muốn giới hạn phạm vi trích xuất; ở chế độ này mặc định tick tất cả, bỏ tick để loại file (có nút Chọn tất cả / Bỏ chọn tất cả phía trên danh sách).

Lọc ngôn ngữ chỉ giữ entry tiếng Anh / tiếng Trung (mặc định cả hai); entry ngôn ngữ khác sẽ bị bỏ qua và ghi rõ lý do trong báo cáo — entry không rõ ngôn ngữ (vd file config) vẫn được giữ lại. Không fail cả đợt khi một ngôn ngữ vắng mặt.

Tick sẵn: toàn bộ chuỗi của mỗi ngôn ngữ đã chọn — từ mọi bundle/.assets/StringTable/CSV — gộp vào đúng 1 file phẳng (en.json hoặc zh.json), giữ thứ tự gốc, không hậu tố #N; trùng key giữ bản đầu và liệt kê xung đột trong extraction_report.txt, nguồn từng key ghi trong file en.provenance.json / zh.provenance.json đi kèm trong extract.zip (để ép lại vào file gốc sau này). Bỏ tick để giữ các file tách theo từng đơn vị (resources.monobehaviour.en.json…). File config (BillingMode, Info…) vẫn xuất riêng như cũ.

Chưa có danh sách file — mở tab này khi đã chọn file IPA/ZIP.

Dịch (Google + từ điển offline)

Chỉ dịch VALUE, giữ nguyên KEY. Bật Google Translate để dịch mọi chuỗi qua Google (cần mạng; dịch theo batch 100 chuỗi/request nên file 1000 chuỗi chỉ mất khoảng chục giây nếu mạng tốt; hàng đợi lưu bền nên tắt tab vẫn tiếp tục được). Nếu Google không dùng được (mất mạng, bị giới hạn tốc độ, trình duyệt chặn CORS) thì tự động thử MyMemory (và LibreTranslate nếu đã cấu hình bên dưới) rồi dùng từ điển offline (~100 từ/cụm thông dụng) và báo rõ lý do + bước nào đã dùng.

Để trống = gọi trực tiếp Google. Có proxy thì dịch qua proxy (cache + giới hạn cứng 500.000 ký tự/tháng, hết hạn mức tự rơi về MyMemory + từ điển offline, không phát sinh phí). Cần tài khoản Cloudflare + API key Google — xem hướng dẫn trong repo (cloudflare/README.md). Mở trang Kiểm tra dịch để thử trực tiếp Google / proxy / MyMemory trên máy này trước khi dịch file lớn.

Bước dự phòng sau MyMemory: chỉ thử khi đã điền endpoint. Bản public libretranslate.com hiện yêu cầu API key (lấy ở portal.libretranslate.com, gói trả phí) — không key thì bước này lỗi và tool rơi về từ điển offline như cũ. Tự host LibreTranslate (miễn phí, mã nguồn mở) thì dán URL instance của bạn, thường không cần key. Endpoint + key chỉ lưu trong trình duyệt này.

Mod — patch TextAsset (menu [1] bản iSH)

Ép bản dịch vào file game theo 4 bước bên dưới: chọn bản dịch → xem trước → cổng kiểm tra → ép và ghi file. File gốc không bao giờ bị ghi đè; output là đơn vị nhỏ nhất đã patch, không phải IPA đóng gói lại.

Bước 1 — Ép lại vào file gốc (E)

Ép bản dịch vào đúng đơn vị (bundle/.assets) theo provenance + key, 1 plan mỗi đơn vị. (E) ghi được TextAsset JSON dạng dict + MonoBehaviour/StringTable — key MonoBehaviour generic (scan path) và bảng ngôn ngữ CÓ type tree vẫn chưa ghi được, sẽ liệt kê rõ là không ép được, không bỏ im lặng. Xem trước (dry-run) trước, rồi mới ghi. Nút ghi chỉ bật sau khi đã xem trước VÀ cổng kiểm tra (bước 6) bên dưới ĐẠT cho đúng file + bản dịch này. File gốc KHÔNG bị ghi đè; output là đơn vị nhỏ nhất đã patch, không phải IPA đóng gói lại; cần re-sign gói ngoài thì game mới nhận. Bundle .unity3d độc lập lớn ghi theo luồng (streaming); bundle v9 chỉ đọc, bundle mã hóa không giải mã.

Chưa chọn nguồn bản dịch.

Chưa chọn file gốc — chọn lại file game đã trích xuất ở trên.

Bước 3 — Cổng kiểm tra trước khi giao (bước 6)

Một cổng kiểm tra duy nhất trước khi giao file: đối chiếu bản dịch với bản gốc (đủ key, không trống), giữ nguyên placeholder/thẻ/xuống dòng, trích lại file đã ép phải khớp bản dịch, font hiển thị phải đủ chữ tiếng Việt đang dùng, và hash/cấu trúc phải khớp kế hoạch ép. Patch pack (mục C7): sau khi Mod thử xong, xuất 1 file .zip gồm manifest JSON + script Python để mang sang iSH/máy tính áp vào file gốc (script mặc định dry-run, chỉ ghi thật với --allow-write, không bao giờ ghi đè file gốc). Asset nhị phân chỉ đọc trên web — pack chỉ chứa thay đổi text.

Tìm theo chữ + nhập file .json (phần B)

Tìm theo CHỮ trong file JSON đang mở — không chỉ tìm theo id (file JSON trích xuất đôi khi không có id): gõ chữ, tool tìm cả trong key lẫn value, mặc định không phân biệt hoa/thường. Sửa trực tiếp entry tìm được ngay trong danh sách, rồi đưa vào ô “Bản dịch” bên dưới để lập plan Mod, hoặc tải file .json đã sửa về. File JSON lấy từ file vừa trích xuất, từ bản dịch xong ở tab Dịch, hoặc nhập từ máy.

Chưa mở file JSON nào — lấy từ file trích xuất, bản dịch, hoặc nhập file .json từ máy.

Kế hoạch Mod (plan JSON — mục 8)

Tách planner/executor: lập plan từ bản dịch (JSON key → giá trị mới, như đầu ra tab Dịch), xem diff từng asset rồi mới áp. Mỗi entry là 1 TextAsset — bỏ tick entry nào thì entry đó giữ nguyên. Plan lưu được (JSON) để mở lại sau; chạy dở thì bấm “Tiếp tục” để chạy tiếp từ checkpoint; “Hoàn tác” khôi phục đúng trước khi áp (theo before_sha). Áp dụng toàn bộ (REBUILD_ALL) ở đây là áp toàn bộ entry trong plan — chế độ ghi REBUILD_ALL của Unity vẫn cần maturity M4 nên chưa dùng được trên web (entry nào để op đó sẽ bị từ chối kèm lý do rõ ràng, các entry khác vẫn áp).

Batch — chạy hàng loạt (menu [4] bản iSH)

Pool worker song song thật — mỗi worker là 1 thread hệ điều hành thật, chạy 1 Pyodide + PB3 riêng (không dùng threading/SharedArrayBuffer), chia nhau từng game; chỉ bên trong một worker thì mỗi game vẫn chạy tuần tự vì Pyodide không có pthreads. Số worker chọn được ở dưới (mặc định 2; tự động 1 khi RAM thiết bị ≤ 4 GB). Mỗi game cô lập: lỗi một game không dừng cả lô. Mặc định chạy thử trước (dry-run): bỏ dấu chọn mới ghi thật. Manifest JSON hoặc CSV (cột: path, mode, locale, old, new, file, object). Chọn tất cả file game ở dưới (đường dẫn trong manifest chỉ cần đúng tên file). Checkpoint từng game được lưu ngay vào IndexedDB sau mỗi game xong — tải lại trang hay tab bị kill giữa chừng vẫn bấm “Tiếp tục” để chạy tiếp phần chưa xong, không làm lại từ đầu. Watchdog 25 giây: quá 25 giây thì worker tự dừng an toàn sau game hiện tại (không kill ngang, không mất checkpoint) — bấm “Tiếp tục” để chạy tiếp. Lưu ý: càng nhiều worker càng tốn RAM (mỗi Pyodide + PB3 — pool 2 worker tốn ~2x RAM so với 1 worker); trên iPhone RAM thấp có thể nặng. Pool lỗi thì tự rơi về 1 worker.

Pool chưa khởi động (bấm “Chạy batch” để khởi động pool worker).

Ma trận hỗ trợ

Sinh từ dữ liệu thật của PB3: registry (maturity hiệu lực), bảng container/Unity của sdk, cột “số game đã test” từ KB của phiên. Không hardcode. Lưu ý: cột “ngày test” hiện “chưa có” vì bản web không kèm file bằng chứng tests/corpus/*.json (chỉ có trên cây iSH); không có mục nào đạt M4.

Nén / giải nén IPA

Nén solid LZMA kiểu WinRAR. File nén ra là bản lưu trữ (.tar.xz), không phải IPA cài trực tiếp. Giải nén file .tar.xz để khôi phục file gốc (giữ nguyên tên gốc) — chọn đúng file .tar.xz đã nén ra rồi bấm Giải nén.

Công cụ font

Quét font TTF xem thiếu bao nhiêu ký tự tiếng Việt (142 mục chuẩn: 134 chữ cái + 8 dấu kết hợp), gộp glyph từ font Be Vietnam Pro đi kèm, hoặc lấy luôn font đi kèm về dùng. Nút “Đọc TMP_FontAsset” đọc tham số atlas SDF (FaceInfo, bảng glyph, độ phủ tiếng Việt) từ file .assets/.unity3d hoặc IPA rồi xuất kế hoạch glyph (chuỗi ký tự thiếu + tham số atlas) để tái tạo atlas trong Unity Editor. Nút “Tạo font fallback” (mục C6, sau khi đã đọc TMP) xuất kế hoạch fallback: tạo TMP_FontAsset MỚI chỉ chứa chữ Việt thiếu rồi đăng ký vào danh sách fallback của TMP_Settings — asset gốc không đổi gì, kèm script C# để tải về. Nút “Liệt kê font của game” (phần D) liệt kê MỌI font trong file đã chọn (TTF/OTF rời, Font object nhúng, TMP_FontAsset) và kiểm từng font đủ bao nhiêu trên 142 mục. Nút “Dùng chung 1 font Be Vietnam Pro” gom mọi font về font Be Vietnam Pro đủ 142/142: TTF rời được gộp thật trên web, TMP chỉ có kế hoạch fallback, còn OTF/TTC/font nhúng chỉ thay được trong Unity Editor — kết quả tải về dạng font_unified.zip. Giới hạn thật: atlas SDF của TextMeshPro không tái tạo được trên web — chỉ tái tạo được trong Unity Editor (script kèm theo).

Chẩn đoán (chỉ đọc)

Inventory + hex dump (512 byte đầu) + quét chuỗi ASCII trong file. Asset nhị phân (texture/âm thanh): chỉ đọc, dùng bản iSH.

Probe định dạng (engine lạ — mục C8)

Probe một file bất kỳ (kể cả file engine lạ, file .pck/.pak/ .locres/.win mà ô chọn file chính không nhận) và trả báo cáo có cấu trúc: định dạng/magic, engine đoán được + độ tin cậy + bằng chứng, thao tác nào được hỗ trợ thật, thao tác nào chưa hỗ trợ, bước tiếp theo. File hoàn toàn lạ vẫn ra báo cáo “chưa hỗ trợ” — không crash, không ghi PASS giả. Nếu không chọn file riêng ở đây thì probe dùng file đã chọn ở trang chính.

Kho tri thức game — KB (menu [3] bản iSH)

KB lưu fingerprint + lựa chọn đã dò của game để lần sau tái dùng (chỉ lưu hash/kích thước/vai trò — không lưu nội dung game hay bản dịch). KB tự lưu vào IndexedDB sau mỗi thay đổi (thêm/quên/ nhập/batch) và khôi phục lại khi mở trang — không cần bấm xuất để giữ. File .sqlite dưới đây vẫn là bản sao lưu chính: xuất định kỳ để phòng khi trình duyệt xóa dữ liệu web.

KB: chưa tải xong — mở tab này sau khi trang khởi động xong.

Cài vào Màn hình chính (giữ KB bền hơn)

Safari có thể xóa dữ liệu web (gồm KB trong IndexedDB) sau ~7 ngày không mở trang, nếu BearTea không được cài vào Màn hình chính. Đã cài thì trình duyệt ít xóa hơn — không đảm bảo tuyệt đối, nên vẫn xuất file .sqlite sao lưu định kỳ (nhắc ở trên).

BearTea đã được cài vào Màn hình chính — trình duyệt sẽ ít xóa dữ liệu web (KB) hơn.

Trên iPhone (Safari): bấm nút Chia sẻ ở thanh công cụ Safari → Thêm vào Màn hình chính → Thêm. Trên Android/Chrome: bấm nút “Cài…” ở trên (hoặc menu ⋮ → Cài đặt ứng dụng).

Nhập KB hợp nhất các game trong file vào KB của phiên này (game trùng bundle id sẽ bị ghi đè). Profile nhập vào chỉ là gợi ý — hash chưa được đối chiếu với file game nên cần dò lại khi dùng.

BearTea là gì?

BearTea là PB3 bản web — công cụ xử lý file game Unity (mở, phân tích, trích xuất, dịch, mod, xuất file) chạy hoàn toàn trên trình duyệt của bạn. File game chỉ được đọc và xử lý trên thiết bị, không upload đi đâu (trừ khi bạn bật dịch Google ở tab Dịch).
